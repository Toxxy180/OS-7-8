Address Translation & Virtual Memory

สรุปเจาะลึกครบทุกหน้า (บทที่ 7: 36 หน้า & บทที่ 8: 27 หน้า) • ความเชื่อมโยง • จำลองภาพ Interactive • ข้อสอบ 40 ข้อพร้อมเฉลย

The Big Picture • ภาพรวมและการเชื่อมโยงเนื้อหา

บทที่ 7 (Address Translation) และ บทที่ 8 (Virtual Memory) เกี่ยวข้องกันอย่างไร?

ทั้งสองบทนี้คือ "เหรียญสองด้านของระบบจัดการหน่วยความจำในระบบปฏิบัติการ (OS Memory Management)" โดย บทที่ 7 (Address Translation) สร้าง "กลไกฮาร์ดแวร์และโครงสร้างตารางในการแปลที่อยู่และดักจับสิทธิ์ (MMU, Page Table, TLB, Trap)" ส่วน บทที่ 8 (Virtual Memory) นำกลไกนั้นมาใช้สร้าง "ภาพลวงตาว่าคอมพิวเตอร์มี RAM ขนาดเกือบอนันต์" โดยใช้ Physical RAM เป็น Cache ให้กับ Disk ผ่านกระบวนการ Demand Paging และอัลกอริทึมการเลือกหน้าที่จะแทนที่ (FIFO, MIN, LRU, Clock)

🎨 อธิบายให้เห็นภาพ: เปรียบเทียบระบบหน่วยความจำเหมือน "ห้องสมุดอัจฉริยะและโต๊ะอ่านหนังสือ"

เพื่อให้เข้าใจเนื้อหาทั้ง 63 หน้าของทั้ง 2 บทได้ทันที ลองนึกภาพตามสถานการณ์ในชีวิตจริงต่อไปนี้:

1. Virtual vs Physical Address
📖 เลขหน้าในสารบัญ vs ชั้นวางจริง

นักศึกษา (CPU) เรียกหาหนังสือด้วย "รหัสประจำตัวของตัวเองที่เรียง 0, 1, 2..." (Virtual Address) แต่บรรณารักษ์ฮาร์ดแวร์ (MMU) จะเป็นคนแปลรหัสนั้นไปหาว่าหนังสือวางอยู่ที่ "ชั้นไหนช่องไหนในห้องสมุด" (Physical Address)

2. Base & Bounds vs Segmentation
📦 เช่าเหมาล็อกเดียว vs แยกโซนวิชา

Base & Bounds คือบังคับให้วางของทุกอย่างรวมกันในล็อกเดียว (ขยายไม่ได้ แชร์กับเพื่อนไม่ได้) ส่วน Segmentation คือแยกเป็นโซนตำราเรียน (Code), โซนสมุดจด (Data), โซนกระดาษทด (Heap/Stack) แยกวางคนละชั้นได้และแชร์ตำราให้เพื่อนอ่านร่วมกันได้ แต่เกิดช่องว่างฟันหลอ (External Fragmentation)

3. Paging & Multilevel Paging
📄 แฟ้มเอกสารขนาด A4 เท่ากันเป๊ะ

Paging หั่นเอกสารทุกแผ่นให้มีขนาดเท่ากัน (Page) และทำช่องเก็บขนาดเท่ากันเป๊ะ (Frame) เสียบช่องไหนก็ได้ที่ว่าง! ส่วน Multilevel Paging คือการทำ "สารบัญของสารบัญ" เพื่อไม่ต้องพิมพ์หน้าสารบัญเปล่าๆ มารอสำหรับหน้าที่ยังไม่ได้เขียน (Sparse Address Space)

4. TLB (Translation Lookaside Buffer)
⚡ โพสต์อิทแปะหน้าโต๊ะ

เพราะการเปิดสารบัญหลายชั้น (Multilevel Page Table) ใช้เวลานาน ซีพียูจึงมี โพสต์อิทใบเล็กความเร็วสูง (TLB) จดว่าหน้าล่าสุดที่เพิ่งเปิดไปอยู่ที่ชั้นไหน ถ้าเจอในโพสต์อิท (TLB Hit) ก็พุ่งไปหยิบได้ทันทีใน 1 ns!

5. Demand Paging & Dirty Bit (บทที่ 8)
🚚 โต๊ะทำงาน (RAM) vs โกดังเก็บของ (Disk)

โต๊ะอ่านหนังสือ (Physical RAM) มีพื้นที่จำกัด ส่วนโกดัง (Disk) ใหญ่มากแต่เดินไปหยิบช้ากว่า 100,000 เท่า! เราจึงวางเฉพาะหน้าที่กำลังอ่านไว้บนโต๊ะ ถ้าเรียกหาหน้าที่อยู่ในโกดังจะเกิด Page Fault ให้เจ้าหน้าที่ (OS Kernel) ไปขนจากโกดังมาวางบนโต๊ะ และถ้าหน้าเก่าบนโต๊ะมีการขีดเขียนแก้ไข (Dirty Bit = Yes) ต้องนำไปอัปเดตเก็บในโกดังก่อนเอาออกจากโต๊ะ

6. Page Replacement (FIFO, MIN, LRU)
🧹 เมื่อโต๊ะเต็ม จะเก็บเล่มไหนกลับโกดัง?

FIFO เอาเล่มที่วางบนโต๊ะนานสุดออก (อาจเผลอเอาเล่มที่ใช้บ่อยออก และเกิด Belady's Anomaly) • MIN มีตาทิพย์รู้อนาคต เอาเล่มที่จะไม่ได้ใช้อีกนานที่สุดออก • LRU ดูอดีตแทนอนาคต โดยเอาเล่มที่ไม่ได้แตะต้องนานที่สุดออก (และใช้ Clock/Nth Chance ประมาณค่าในระบบจริง)

🗺️ แผนผังเชื่อมโยงการทำงานตั้งแต่ต้นจนจบ (End-to-End Flow: บทที่ 7 ➔ บทที่ 8)

📊 ตารางสรุปวิวัฒนาการของเทคนิคในบทที่ 7 สู่บทที่ 8 (ทำไมต้องมีวิธีถัดไป?)

เทคนิค / หัวข้อ อยู่ในหน้า หลักการทำงานสำคัญ จุดเด่น (Pros) ข้อจำกัด (Cons) ที่นำไปสู่วิธีถัดไป
1. Base and Bounds บทที่ 7 หน้า 6–9 บวกค่า Base และเช็คขอบเขตกับ Bound เป็นก้อนเดียว ง่าย เร็วมาก ใช้ฮาร์ดแวร์น้อย ย้ายที่ใน RAM ได้ กันเขียนทับ Code ตัวเองไม่ได้, แชร์ไม่ได้, ขยาย Stack/Heap ยาก
2. Segmentation บทที่ 7 หน้า 10–16 แบ่งเป็นหลาย Segment (Code, Data, Heap, Stack) มีตารางเก็บ Base/Bound/Access แชร์เซกเมนต์ได้, ป้องกัน Code ได้, ขยาย Stack/Heap ได้อิสระ จัดสรรพื้นที่ขนาดไม่เท่ากันยาก, เกิด External Fragmentation
3. Paging (ชั้นเดียว) บทที่ 7 หน้า 17–23 แบ่งหน่วยความจำเป็น Page และ Frame ขนาดคงที่เท่ากัน ใช้ Bitmap จองง่าย ไร้ปัญหา External Fragmentation, จัดสรรหน้าว่างง่ายมาก เมื่อเจอ Sparse Address Space ตาราง Page Table จะใหญ่โตมหาศาล
4. Multilevel Translation บทที่ 7 หน้า 24–30 จัดตารางเป็นต้นไม้ (Paged Seg / Multilevel Paging) สร้างเฉพาะกิ่งที่ใช้จริง ประหยัดพื้นที่ตารางใน Sparse Address Space, แชร์ได้ทั้งระดับ Page/Segment ต้องเข้าถึงหน่วยความจำหลายครั้ง (2+ Lookups) ต่อการแปลงที่อยู่ 1 ครั้ง
5. TLB (Translation Cache) บทที่ 7 หน้า 31–36 แคชฮาร์ดแวร์เก็บคำแปล Virtual Page ➔ Frame ล่าสุด ทำให้การแปลงที่อยู่หลายระดับกลับมาเร็วระดับ ~1 ns เมื่อเกิด TLB Hit ถ้า RAM เต็มหรือต้องการรันโปรแกรมใหญ่กว่า RAM ต้องพึ่งบทที่ 8!
6. Demand Paging & MMap บทที่ 8 หน้า 1–19 ใช้ RAM เป็นแคชของ Disk ดึงหน้าเมื่อเกิด Page Fault (13 ขั้นตอน) + Dirty/Use Bit ให้ภาพลวงตาหน่วยความจำขนาดเกือบอนันต์, Zero-copy File I/O เมื่อ RAM เต็ม ต้องมีนโยบายเลือกหน้าที่จะไล่ที่ (Evict) ที่ฉลาด
7. Page Replacement บทที่ 8 หน้า 20–27 เปรียบเทียบ FIFO, MIN (Optimal), LRU, LFU และ Clock/Nth Chance MIN ดีสุดในทฤษฎี, LRU ประมาณค่า MIN ได้ดีเมื่อมี Locality, Clock ใช้จริงใน OS FIFO เกิด Belady's Anomaly ได้; Sequential scan ใหญ่กว่าแคชทำให้ FIFO/LRU พัง
